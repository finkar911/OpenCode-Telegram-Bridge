# OpenCode Telegram Bridge

**English version:** [README.md](README.md)

Sidecar-сервис: присылает в Telegram события сессий OpenCode и позволяет ставить
новые задачи из бота. Не требует плагинов OpenCode. Это самостоятельный сервис:
ему нужны только запущенный OpenCode и Telegram-бот.

Интерфейс бота двуязычный: **English по умолчанию** и **Русский**. Язык
переключается в `/settings` (кнопка «⚙️ Settings / Настройки») и сохраняется
между перезапусками.

## Что реализовано

1. **Старт работы** — `session.execution.started` → сообщение «Начали выполнять»
   с проектом, названием сессии и задачей. Если сессия автоматически продолжается
   после субагентов, приходит «Продолжаю выполнять задачу» и последний текст,
   который агент добавил к работе, а не повтор исходной задачи.
2. **Уточняющие вопросы** — `form.created` → вопрос с кнопками вариантов или
   полем для текста. В сообщении перечислены варианты с номерами и описаниями,
   как в OpenCode; кнопки тоже пронумерованы, а «Ввести свой ответ» идёт
   отдельным пунктом. Ответ уходит обратно через
   `POST /api/session/{id}/form/{formID}/reply`. Разрешения инструментов
   (`permission.asked`) тоже приходят с кнопками «Разрешить / Всегда / Отклонить».
3. **Завершение** — `session.execution.succeeded/failed/interrupted` → проект,
   сессия, последний текст ассистента, длительность, стоимость и токены.
   Формат ответа выбирается в `/settings`: HTML-превью, блок MD-кода или
   чистый текст. Он применяется ко всем уведомлениям и к блоку «Последнее» в
   карточке сессии. `.md` файл — всегда, только когда текст не помещается в
   сообщение, или никогда — работает для всех типов уведомлений. Если у сессии
   ещё работают субагенты, вместо `succeeded` показывается
   `Итог: waiting sub agents`; `Итог: succeeded` появляется, когда активных
   субагентов не осталось. Если текст заканчивается на `?`, добавляется кнопка
   «Ответить». В карточке завершения есть «Открыть сессию» и «Продолжить»:
   вторая кнопка ставит эту же сессию активной и сразу ждёт новый текст, чтобы
   дополнить ТЗ без создания новой сессии.
4. **Выбор проекта/сессии и новая задача** — `/projects`, `/sessions`, карточка
   сессии, «Продолжить сессию», «Новая задача». Новая задача создаёт сессию в
   выбранной папке и отправляет prompt через API.

## Архитектура

```text
Telegram Bot API
   ⇅  long polling (входящих портов нет)
bridge.js  (Node 18+, без npm-зависимостей)
   ├── config.js    env, owner ID, PIN, состояние offset
   ├── opencode.js  HTTP + SSE клиент OpenCode
   ├── telegram.js  Bot API клиент
   ├── ui.js        тексты, кнопки, валидация ответов
   ├── i18n.js      английские и русские строки
   └── bot.js       команды, формы, разрешения, уведомления
   ⇅  Basic auth из service.json
OpenCode background service (проверено на 2.3.2)
   GET  /api/event
   GET  /api/info
   GET  /api/project
   GET  /api/model
   GET  /api/session
   GET  /api/session/active
   GET  /api/session/{id}
   GET  /api/session/{id}/message
   GET  /api/session/{id}/form
   GET  /api/session/{id}/permission
   POST /api/session
   POST /api/session/{id}/prompt
   POST /api/session/{id}/model
   POST /api/session/{id}/form/{formID}/reply
   POST /api/session/{id}/permission/{requestID}/reply
```

Сервис и пароль читаются из `%USERPROFILE%\.local\state\opencode\service.json`.
Если OpenCode перезапустился и сменил порт/пароль, bridge перечитывает файл при
переподключении. Переменные `OPENCODE_URL` и `OPENCODE_PASSWORD` позволяют
задать сервер вручную.

## Установка

Требуется Node.js 18.16+ и запущенный OpenCode.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и возьмите токен.
2. Узнайте свой числовой Telegram ID через [@userinfobot](https://t.me/userinfobot).
3. Откройте бота и нажмите **Start** — бот не может написать первым.
4. Создайте файл окружения:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.config\opencode" | Out-Null
Copy-Item .env.example "$env:USERPROFILE\.config\opencode\telegram.env"
notepad "$env:USERPROFILE\.config\opencode\telegram.env"
```

Минимум:

```dotenv
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_OWNER_ID=123456789
TELEGRAM_PIN=1234
TELEGRAM_PROJECT_ALIASES={"my-project-id":"My Project"}
```

5. Проверка без запуска бота:

```powershell
node bridge.js --check
```

До настройки токена команда завершается с кодом 1 и пишет
`Telegram NOT CONFIGURED`. После заполнения env ожидаемый результат:

```text
OpenCode: 2.3.2 at http://127.0.0.1:28894
Projects: 6 (4 unique paths)
Recent sessions: 5
Result: OpenCode OK · Telegram OK
```

6. Запуск:

```powershell
node bridge.js
```

7. Напишите боту `/start`.

### Автозапуск в Windows

Task Scheduler → «Создать задачу»:

- Триггер: «При входе в систему»;
- Действие: полный путь к `node.exe` (узнать: `where.exe node`) с аргументом
  `C:\Tools\OpenCodeTelegramBridge\bridge.js`;
- Рабочая папка: корень репозитория, например
  `C:\Tools\OpenCodeTelegramBridge`;
- Запускать только для текущего пользователя (тот же пользователь, что у OpenCode).

Не запускайте два bridge с одним токеном: Telegram вернёт `409 Conflict` на
`getUpdates`.

## Команды и кнопки

| Команда | Назначение |
| --- | --- |
| `/menu` | показать клавиатуру с тремя кнопками (служебное сообщение `⌨️`) |
| `/projects` | проекты OpenCode |
| `/sessions` | избранные сессии; остальные — в подменю «Все сессии» |
| `/new` | новая задача: выбрать проект → отправить текст |
| `/status` | версия OpenCode, выбранная сессия, PIN, язык |
| `/settings` | язык бота, формат ответа, вложения и типы уведомлений |
| `/lock` | немедленно заблокировать действия |
| `/unlock <PIN>` | разблокировать на `TELEGRAM_UNLOCK_MINUTES` |
| `/cancel` | отменить текущий ввод |
| `/id` | показать свой Telegram ID |
| `/help` | справка и постоянная клавиатура |
| `/start` | меню, справка и постоянная клавиатура (последняя в списке) |

- **Проект** → избранные сессии проекта; остальные — в «Все сессии».
- **Сессия** → карточка с ID, стоимостью, токенами и последним текстом.
  «Продолжить сессию» отправляет новое сообщение в **эту же** сессию и не
  создаёт новую. «Новая задача» создаёт **отдельную** сессию в проекте и
  отправляет текст туда.
- **Выбранная сессия сохраняется.** После открытия карточки можно сразу
  отправить текст — он уйдёт в эту сессию. Уведомления о старте/завершении
  других задач не сбрасывают выбор, поэтому заново выбирать сессию не нужно.
- **Вопрос формы** → кнопки вариантов. В тексте вопроса есть нумерованный
  список с описаниями вариантов; в подтверждении ответа сохраняются номер и
  название выбранного пункта. Для `multiselect` кнопки переключаются, затем
  «Готово». Если поле необязательное, можно нажать «Пропустить» или отправить
  `/skip`.
- **Разрешение** → «Разрешить» (один раз), «Всегда», «Отклонить».

## Меню бота

`/menu` переустанавливает постоянную клавиатуру с тремя основными действиями.
Telegram не позволяет установить reply-клавиатуру совсем без сообщения, а
пустой/невидимый текст отклоняет (`text must be non-empty`). Поэтому команда
отправляет одно короткое служебное сообщение `⌨️` без звука и оставляет его:
именно это сообщение и устанавливает кнопки. Удалять его нельзя — вместе с ним
исчезает и клавиатура.

`/start` показывает справку и тоже устанавливает клавиатуру. В нативном меню
Telegram `/menu` стоит первой командой, `/start` — последней.

Клавиатура:

```text
📁 Projects     🕘 Sessions     ➕ New task
```

- Кнопки отправляют обычный текст, bridge распознаёт их и выполняет действие.
- Клавиатура локализована; после смены языка в `/settings` она заменяется.
- Остальные действия (`status`, `settings`, `help`, `id`, `cancel`, `lock`,
  `unlock`) доступны только через команды и нативное меню Telegram.
- Для `en` и `ru` регистрируется нативное меню команд (`setMyCommands`), а
  кнопка «Меню» открывает список команд (`setChatMenuButton`).
- В одном сообщении Telegram нельзя совместить reply-клавиатуру и inline-кнопки,
  поэтому `/start` показывает постоянную клавиатуру. Inline-кнопки остаются там,
  где они нужны для выбора: проекты, сессии, карточки, `/settings` (язык) и
  вопросы форм.

## Формат сообщений и вложений

Формат выбирается в `/settings` → **🎨 Формат / Format** и применяется ко всем
уведомлениям: старт, продолжение, субагенты, вопросы, разрешения, завершение и
закрытие формы. В карточке сессии форматируется блок **«Последнее»**.

1. **С форматированием (HTML)** — заголовки, жирный текст, код, списки,
   ссылки и блоки цитат; сырые `#`, `**` и тройные обратные кавычки в сообщение
   не попадают. Служебные подписи и ID экранируются и не превращаются в
   курсив/жирный.
2. **Блок MD-кода** — всё сообщение целиком в одном `<pre><code>` блоке, как
   исходный Markdown.
3. **Без форматирования** — исходный текст как есть, без HTML-разметки.

Вложение выбирается в `/settings` → **📄 Полный ответ / Full result** и
работает для всех типов уведомлений:

1. **Всегда** — `.md` файл приходит после каждого уведомления.
2. **Только если не помещается в сообщение** — файл добавляется, когда текст
   уведомления обрезан или длиннее лимита Telegram.
3. **Никогда** — приходит только сообщение.

Что попадает в файл:

- для завершения задачи — полный ответ ассистента;
- для остальных уведомлений — полный текст уведомления без обрезки;
- файл приходит следующим сообщением и привязан к сообщению
  (`reply_to_message_id`);
- называется `Проект_Название сессии_ГГГГ-ММ-ДД ЧЧ-ММ-СС.md`; запрещённые в
  Windows символы заменяются на `-`.

Особенности:

- карточка сессии форматируется, но файл не прикладывает — это не уведомление;
- первый вопрос формы приходит с файлом, последующие шаги формы форматируются
  без нового файла;
- превью ограничено по длине; при обрезке показывается пометка, что полный
  текст в файле (или просто «сокращено», если файл отключён);
- таблицы Markdown в превью остаются текстом; в `.md` файле они сохраняются
  как есть.

## Кнопка «Продолжить»

В карточке завершения кнопка **💬 Продолжить / Continue** заменяет «Новую
задачу». Она выбирает ту же сессию и просит следующий текст, поэтому можно
сразу дополнить ТЗ. Новая отдельная сессия по-прежнему создаётся кнопкой
**➕ Новая задача** в постоянной клавиатуре и командой `/new`.

## Выбор модели сессии

В карточке сессии есть кнопка **🧠 Модель / Model**:

1. выбрать провайдера (`commandcode`, `opencode`, `routerai`, ...);
2. выбрать модель (по 10 на страницу);
3. если у модели есть варианты — выбрать `low/medium/high/max` или
   «По умолчанию».

Текущая модель отмечена `✅`. Выбор применяется к последующим ходам сессии
через `POST /api/session/{id}/model` и сохраняется в OpenCode. Список моделей
берётся из `/api/model` для директории проекта.

У новой сессии первый prompt уходит с моделью по умолчанию; после создания
модель можно сменить в карточке, и следующие задачи пойдут уже с ней.

> **Особенность OpenCode Desktop 2.3.2:** если сменить модель из Telegram, пока
> сессия открыта в Desktop, селектор внизу может продолжать показывать старую
> модель до переоткрытия сессии. Сама сессия уже использует новую модель, а
> карточка сессии в Telegram показывает актуальное значение. Переоткройте
> сессию, чтобы обновить композер. В режиме steer Desktop может переключить
> сессию обратно на модель, выбранную в его композере, поэтому обновите сессию
> перед отправкой из Desktop.

## Изображения

Изображения можно прикреплять в двух сценариях:

- после **«Новая задача»** — вместе с текстом задачи;
- после **«Продолжить сессию»** — вместе с новым ТЗ в существующую сессию.

- Подпись к фото (`caption`) становится текстом задачи. Если подписи нет,
  отправляется стандартная инструкция «Проанализируй прикреплённое изображение».
- Поддерживаются фото Telegram и документы с MIME `image/*`.
- Альбом из нескольких фото группируется в одну задачу/сообщение.
- Лимит — 20 МБ на изображение (ограничения Telegram Bot API и OpenCode).
- Изображение передаётся в OpenCode как `files` с `data:image/...;base64,...`
  в `POST /api/session/{id}/prompt`; агент видит его как вложение.
- Без активного сценария «Новая задача»/«Продолжить сессию» изображение
  отклоняется с подсказкой.

Модель должна поддерживать изображения (у текущей модели в конфиге
`attachment: true`).

## Избранные сессии

- В карточке сессии есть кнопка **☆ В избранное / ⭐ В избранном**; нажатие
  добавляет или убирает сессию. Выбор сохраняется в `state.favoriteSessions`.
- `/sessions` показывает **только избранные** сессии по всем проектам.
- Внутри проекта список сессий тоже сначала показывает избранные.
- Кнопка **«📚 Все сессии»** открывает полный список; избранные в нём отмечены
  `⭐`.
- Списки постраничные (по 10), работают и глобально, и внутри проекта.
- Если избранных пока нет, показывается подсказка и кнопка «Все сессии».

## Статусы сессий

В списке сессий у каждой сессии есть иконка последнего состояния:

| Иконка | Статус |
| --- | --- |
| ✅ | завершена (`succeeded`) |
| ❌ | ошибка (`failed`) |
| ⏹ | прервана (`interrupted`) |
| ❓ | ждёт ответа на вопрос формы |
| 🔐 | ждёт разрешения инструмента |
| 🔄 | выполняется |
| ⏳ | ждёт субагентов (сама простаивает) |
| ⚪ | нет данных / ожидание |

Приоритет: вопрос формы → разрешение → выполняется → ждёт субагентов →
итог сессии. Статус берётся из `GET /api/session/active`,
`GET /api/session/{id}/form` и `GET /api/session/{id}/permission`.
Под списком выводится краткая легенда на выбранном языке.

## Язык интерфейса

- По умолчанию — **English**.
- `/settings` или кнопка **Settings / Настройки** в главном меню; выбор
  `English` / `Русский` сохраняется в `state.json`.
- Язык меняет все новые сообщения, кнопки, ошибки и уведомления; уже
  отправленные сообщения не перерисовываются.
- Тексты вариантов формы приходят от модели и не переводятся.

## Настройки ответа

`/settings` → **🎨 Формат / Format** и **📄 Полный ответ / Full result**.

- Формат: с HTML-разметкой, блок MD-кода или без форматирования.
- Вложение: всегда, только если не помещается в сообщение, или никогда.

Обе настройки сохраняются в `state.responseFormat` и `state.attachFullResult`
и переживают перезапуск. Формат применяется ко всем новым уведомлениям и к
блоку «Последнее» в карточке сессии; вложение — ко всем типам уведомлений.
Уже отправленные сообщения не меняются.

## Настройки уведомлений

`/settings` → **🔔 Уведомления / Notifications**. Можно отдельно включить или
выключить:

- **Начали выполнять** — первый старт задачи;
- **Продолжаю выполнять задачу** — только автоматическое продолжение самой
  сессии (например, после результатов субагентов). Новый текст, отправленный
  пользователем в существующую сессию, считается новым стартом и приходит как
  «Начали выполнять» с этим текстом;
- **Сессия ждёт субагентов** — родительская сессия завершила шаг, но дочерние
  ещё работают;
- **Вопросы** — формы и ответы на них;
- **Разрешения** — запросы разрешений инструментов;
- **Завершение** — финальный успех, ошибка или прерывание.

Есть кнопки «Включить все» / «Отключить все». По умолчанию включены все шесть
типов. Настройки сохраняются в `state.notifications` и переживают перезапуск.
«Продолжаю выполнять задачу» и «Сессия ждёт субагентов» теперь независимые
переключатели, а не части старта/завершения.

Если тип отключён, сообщения в чат не отправляются, но состояние остаётся
видимым в информации о сессии и в списке сессий: `❓` (вопрос), `🔐`
(разрешение), `⏳` (субагенты), `🔄` (выполняется), `✅/❌/⏹` (итог).
Статусы считаются напрямую из API OpenCode и не зависят от настроек уведомлений.

## Авторизация и безопасность

- **Один владелец.** Сообщения и кнопки от любого другого `from.id` молча
  игнорируются; группа тоже игнорируется, даже если владелец там состоит.
- **PIN как второй фактор.** Если `TELEGRAM_PIN` задан, действия доступны только
  после `/unlock`. 5 неверных попыток → блокировка ввода PIN на 15 минут.
  После перезапуска bridge состояние разблокировки сбрасывается, нужен новый
  `/unlock`. Уведомления при этом продолжают приходить в личный чат владельца.
- **Long polling.** Bridge не открывает входящий HTTP-порт, поэтому снаружи
  доступен только исходящий трафик к `api.telegram.org`.
- **Секреты вне репозитория.** Токен и пароль OpenCode лежат в
  `%USERPROFILE%\.config\opencode\telegram.env`, а не в git. Ограничьте ACL:

```powershell
icacls "$env:USERPROFILE\.config\opencode\telegram.env" /inheritance:r /grant:r "$env:USERNAME:(R,W)"
```

- **Редактирование исходящего текста.** Токен бота, пароль OpenCode и типовые
  ключи (`sk-…`, `ghp_…`, `xox…`) заменяются на `***`.
- **Границы доверия.** Bridge имеет полный доступ к сессиям OpenCode. Запускайте
  его от той же непривилегированной учётной записи Windows, что и OpenCode, и не
  публикуйте API OpenCode в сеть. Компрометация Telegram-аккаунта позволяет
  читать уведомления; PIN защищает только действия. При утечке токена
  перевыпустите его в BotFather.

## Как определяются события

| Сценарий | Событие OpenCode | Что делает bridge |
| --- | --- | --- |
| Начали выполнять | `session.execution.started` | читает сессию и последнее user-сообщение |
| Уточняющий вопрос | `form.created` | рисует поля формы, принимает ответ |
| Разрешение | `permission.asked` | кнопки `once/always/reject` |
| Завершение | `session.execution.succeeded` | последний assistant-текст; при активных субагентах — `waiting sub agents` |
| Ошибка | `session.execution.failed` | текст ошибки и статистика |
| Прерывание | `session.execution.interrupted` | отметка «прервана» |
| Вопрос закрыт в TUI | `form.replied`, `form.cancelled` | помечает вопрос закрытым; старые кнопки отвечают «устарело» |

Подагенты по умолчанию не создают отдельные уведомления о старте/финише
(`NOTIFY_SUBAGENTS=false`), но их вопросы и разрешения приходят с пометкой
«субагент»: они могут блокировать работу.

Статус в карточке сессии:

- `running` — выполняется сама сессия;
- `waiting sub agents` — сессия завершила свой шаг, но дочерние сессии ещё
  работают (в OpenCode это тот самый индикатор-«радар»);
- `succeeded` / `failed` / `interrupted` — активных субагентов нет, работа
  действительно завершена.

`waiting sub agents` определяется через `GET /api/session/active` и цепочку
`parentID`; субагент может быть не прямым ребёнком, а внуком.

### Почему проектов и сессий меньше, чем в API

OpenCode может хранить несколько записей проекта с одним и тем же `canonical`
путём (legacy-запись `global`, старые ID после обновлений). Bridge группирует
такие записи по пути и показывает самую свежую. Поэтому в списке один
`C:\Projects\Demo`, а не три.

Сессии проекта запрашиваются по `directory` (а не по конкретному `projectID`)
и только с `parentID=null`. Это объединяет сессии дублирующихся записей и
скрывает субагентов — так список совпадает с деревом сессий в UI OpenCode.
Вопросы и разрешения субагентов при этом продолжают приходить.

## Ограничения

- События не воспроизводятся задним числом: если bridge был выключен, старт и
  финиш этой сессии он не пришлёт. Telegram offset сохраняется, поэтому старые
  команды повторно не выполняются.
- Надёжный вопрос — только через инструмент `question` (форма). Если агент задал
  вопрос обычным текстом, bridge увидит завершение и, при вопросительном знаке в
  конце, покажет эвристическую кнопку «Ответить».
- Поддерживаются текст и изображения; голосовые сообщения и произвольные
  не-image файлы не отправляются.
- Один владелец, без ролей и мультипользовательского доступа.
- Итоговое «резюме» — последний текст модели, а не отдельный пересказ. Превью
  может быть обрезано; полный текст приходит в `.md` файле, если включено
  вложение.
- PIN хранится в plaintext в локальном env-файле; защита — ACL файла.

## Проверки

```powershell
node --test test
node bridge.js --check
```

Тесты не ходят в сеть: Telegram и OpenCode подменяются фейками. Проверяются
авторизация, PIN/lockout, форматирование, формы, разрешения, создание задачи и
фильтрация старых assistant-сообщений.

## Диагностика

- `--check` пишет `OpenCode: ERROR` — проверьте, что OpenCode запущен и существует
  `%USERPROFILE%\.local\state\opencode\service.json`.
- Бот молчит — нажмите Start, сверьте `TELEGRAM_OWNER_ID`, проверьте, что запущен
  только один bridge.
- `401 Unauthorized` от OpenCode — устарел пароль в `service.json`; перезапустите
  bridge, он перечитает файл.
- Кнопки вопроса «устарели» после перезапуска bridge — состояние форм живёт в
  памяти; ответьте на вопрос в OpenCode или дождитесь нового события.
- Offset хранится в `%USERPROFILE%\.local\state\opencode-telegram-bridge\state.json`.
  Удалять его без необходимости не стоит: Telegram заново отдаст последние
  команды.
